## 可用于 PR 正文的内容

本改动将原有交互流程整理为自托管 Docker / Web 应用：用户在网页完成学校登录、选择并确认本人实际位置，最终确认后发送单次请求并回读学校记录。服务端包含网页静态资源、单进程多线程 Waitress 和仅登录期间运行的 Chromium，不要求用户安装本地 Python。

主要变化：

- 多用户工作台、学校 CookieJar、浏览器 context、操作锁、CSRF 和确认令牌隔离；保留学校交互验证。
- 学校会话以 AES-256-GCM 加密包保存在用户浏览器，后端按需只读验证并恢复；服务器保留独立加密密钥、恢复许可及最小防重复日志，不保存学校密码。
- 同一账号同一天争抢持久化唯一提交机会，结果不明时不自动重发；提交成功以学校记录回读确认。
- Docker 默认只启动应用，映射到宿主机回环端口；支持已有容器代理的共享网络。域名、证书与公网反向代理由部署者管理。
- 提供仅依赖 Python 标准库的交互安装器，要求运维输入自己的天地图 Key，保存权限 0600 的本地环境文件后构建并等待应用健康；重复安装保留已有内部密钥、项目与其他自定义配置，支持仅配置和已有代理网络。
- 地图支持天地图官方 HTTPS 矢量底图与中文注记，部署者配置专用 Key 后优先使用；保留 OSM，可显式切换、失败重试，切换不改变已保存坐标。不增加地图代理或外部脚本 SDK。
- 显式配置完整 HTTPS origin，支持非标准端口；保留可信代理头、Host / Origin / CSRF、Secure Cookie、CSP、限速、超时及单实例约束。
- 删除内置 Caddy 及证书编排，提供后端安装、配置、升级、回滚、整卷备份与接入约定。
- 修正严格 CSP 下的浏览器等待谓词，以及关闭页面 / context 时与 `route.fetch()` 的竞争；为延迟轮询和延迟响应清理加入回归场景。
- 镜像显式规范公开代码与资源权限，在非 root 下检查导入与静态资源读取，兼容严格 umask 生成的构建上下文；构建代理与应用运行时出口配置分开。
- 本分支只维护 Docker / Web，移除 Windows / APK 及相关工作流；独立离线模拟器保留于源码，不进入生产镜像。

本次打包调整不改变现有数据库、加密包格式或学校业务协议，不增加定时提交功能。
