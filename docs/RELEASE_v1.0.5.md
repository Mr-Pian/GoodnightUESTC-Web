提供自托管 Docker / Web 发行：服务器运行网页、Waitress 和登录期间使用的 Chromium；运维自行接入域名、HTTPS 与反向代理。

- 增加 Docker、Compose、buildx 的构建前检查，缺少构建插件或 daemon 权限时在依赖下载前提示。
- 支持 `python3 deploy/install.py --image ghcr.io/mr-pian/goodnightuestc-web:1.0.5`，在终端输入自己的 HTTPS 地址与天地图 Key，直接拉取发行镜像。
- 附带完整源码部署包、逐条命令的 `DEPLOYMENT.md` 与 `SHA256SUMS`。需要自行构建时，包内保留 Dockerfile、安装器和全部源码。
- 补充 pip、APT、Chromium 与运行时出口的区别，以及天地图 Key、部署 origin、浏览器 Referer 白名单的排错步骤。
- 包含服务器资源预算、观测命令、更新和保留数据卷的回滚说明。

发行镜像平台为 **Linux amd64**。镜像与源码包不含部署者域名、真实 `.env`、地图 Key、学校凭据或业务数据；地图 Key 由每位运维在自己的服务器配置，使用网页时会出现在浏览器地图请求中。

默认端口为 `127.0.0.1:18090 → 容器 8090`，仅运行 `backend`。HTTP 健康检查通过后，仍需按部署文档接入自己的 HTTPS 入口。学校登录与单次确认流程、多用户隔离、会话恢复和持久化防重复保留；本版本不新增定时操作，也不改变数据库或会话包格式。

发布工作流要求合成测试、容器构建、非 root / Chromium、Web 与会话冒烟及代理契约检查通过。它们不代表真实学校提交成功，不覆盖全部设备和网络环境。资源数字是规划预算，尚无并发承载基准。

首次发布 GHCR 包后，维护者需要确认包的访问级别为 Public，并从未登录环境测试拉取。若包尚未开放匿名拉取，可暂用源码构建方式；不要向用户分发个人 GitHub token。
