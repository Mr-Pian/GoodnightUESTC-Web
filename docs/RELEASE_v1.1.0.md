本版本修复学校明确拒绝提交后当天仍被锁定的问题，并改进浏览器保存会话的恢复、错误提示与发行流程。

- **明确拒绝后允许本人手动重试**：前次尝试已保存为 `rejected` 时，可重新预检查、取得新的确认令牌并再次勾选确认后提交。兼容旧版拒绝记录，无需迁移或删库。正在执行、已确认或结果不明的尝试继续防重；真实签到 POST 不自动重发。
- **提交失败更易排查**：展示学校业务码、HTTP 状态及脱敏后的错误文字，补充 Cookie 值脱敏；不保存原始学校响应。`PENDING` 本身不能证明前一次请求没有写入。
- **改进学校会话恢复**：签到应用授权失效时，通过只读 GET 重新进入应用并再次校验；不启动 Chromium、不使用学校密码。学校认证真正失效时仍需本人登录。页面区分未找到本机包、存储不可用与恢复失败，并提供浏览器重开后的排查步骤。
- **改进发行检查**：构建前检查 `VERSION`、目标标签及对应发行说明。手动运行时可留空版本输入，直接从所选提交读取版本；不匹配时明确显示实际值和预期值。

本次修复已通过 111 项合成单元测试，以及明确拒绝后再次确认重试、关闭重启 Chrome 进程后恢复会话等 mock 界面检查。上述结果不代表真实学校提交成功，也不能保证所有设备或跨日学校会话都有效；当前提交的容器构建与发行验证以 GitHub Actions 结果为准。

**升级需保留原项目名、完整 `/data` 数据卷、内部密钥与部署 origin，禁止使用 `docker compose down -v`。** 本版本不改变数据库或会话包格式。保留旧版镜像与整卷备份，以便按部署文档回滚。会话恢复仍依赖同一浏览器设备 Cookie、本机会话包、服务器密钥、恢复许可及学校会话有效期。

发行平台为 **Linux amd64**，镜像为 `ghcr.io/mr-pian/goodnightuestc-web:1.1.0`，附带完整源码部署包、逐条命令的 `DEPLOYMENT.md` 和 `SHA256SUMS`。安装命令：

```sh
python3 deploy/install.py --image ghcr.io/mr-pian/goodnightuestc-web:1.1.0
```

Docker 只运行应用，默认映射 `127.0.0.1:18090 → 容器 8090`；域名、HTTPS 与反向代理由部署者接入。配置自己的天地图 Key，不在仓库或公开反馈中提供真实 `.env`、凭据、会话包或数据卷。浏览器使用地图时，地图 Key 会出现在浏览器地图请求中，应在天地图平台配置来源限制与配额。
